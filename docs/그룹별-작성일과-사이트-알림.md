# 그룹별 작성일과 사이트 내 안내

## 운영 순서

1. 회원은 `/membership/talk`에서 ‘내 모임 일정 · 격주 금요일 오후 6시’처럼 1주차 모임 기준의 요일과 시간을 확인합니다. 시간이 지나도 기준 주차는 바뀌지 않습니다. 그룹 이름과 희망 요일 입력 기능은 표시하지 않습니다. 기존 희망 요일 데이터는 보존하지만 새 입력·수정은 차단합니다.
2. 운영자는 `/admin/cohorts`의 그룹과 작성 일정 관리에서 그룹을 만들고 회원을 배정합니다. 기수마다 한 그룹에 소속되며 최대 6명입니다. 구성 중에는 4명 미만도 저장됩니다.
3. 각 그룹의 1·3·5·7주차 모임 날짜와 시각을 한국 시간으로 입력합니다. 첫 모임을 정하고 2주 간격으로 채운 뒤 특정 주차를 조정할 수 있습니다.
4. 회원은 온라인 대화 목록과 해당 주차 상단에서 `○월 ○일(요일) 밤 11:59까지 작성해주세요.`를 확인합니다.

운영자 화면의 일정 저장은 기수 시작 전 날짜와 새로 입력·변경한 과거 시각을 거절합니다. 이미 저장된 지난 모임 시각을 그대로 두고 이후 일정만 조정하는 것은 허용합니다. 이 검사는 웹 서버의 저장 동작에 적용됩니다.

그룹 추가와 회원 배정 영역은 접고 펼칠 수 있습니다. 그룹 제목은 `그룹 이름 · 0/6명`으로 표시하며, 펼치면 이름과 일정을 수정합니다. 제목 오른쪽의 삭제 버튼은 빈 그룹에서만 사용할 수 있고 확인 후 해당 그룹과 모임 일정을 삭제합니다. 회원이 있는 그룹은 DB에서도 삭제를 차단합니다. 작성된 답변은 삭제하지 않습니다.

## 작성 일정

- 사전 질문: 그룹의 해당 모임 날짜에서 달력 기준 2일 전 23:59입니다. 모임 시각에서 정확히 48시간 전을 뜻하지 않습니다.
- OUTPUT: 바로 앞 홀수 주차 모임이 있는 주의 다음 주 일요일 23:59입니다. 예를 들어 10월 2일 모임은 10월 11일 마감입니다. 그룹별 실제 모임 날짜로 계산합니다.
- 날짜 경과에 따른 저장 차단은 없습니다. 기수 종료와 지난 기수의 읽기 전용 규칙은 유지합니다.
- 1주차 사전 질문만 기수 시작일에 공개합니다. 3·5·7주차 사전 질문은 모임 7일 전 같은 시각, 실천 기록은 모임 다음 날 한국 시간 0시에 공개합니다. 모든 작성 마감은 실제 모임일 기준입니다. 시작일 기록과 기존 닉네임 잠금 정책, 종료일의 읽기 전용 전환은 유지합니다.
- 미배정 또는 모임 날짜 미정이면 1주차를 제외한 해당 주차를 ‘일정 준비 중’으로 잠그며 작성일과 알림도 만들지 않습니다. 1주차는 기수 시작일에 열리지만 모임일 확정 전에는 마감을 안내하지 않습니다. 지난 기수와 종료된 기수는 기존 읽기 전용 접근을 유지합니다.
- 1~8주차 답변은 그룹 구분 없이 같은 기수 전체와 공유합니다. 해당 주차에 자기 답변을 먼저 남겨야 동료 답변이 열립니다. 다른 기수 접근과 지난 기수 읽기 전용 규칙은 그대로 유지합니다. 그룹 배정은 일정 계산에만 사용합니다.

## 사이트 내 안내

- 위치: `/membership`와 `/membership/talk`의 상단 작성 안내 카드.
- 대상: 현재 진행 중인 기수의 미작성자. 아직 공개되지 않은 주차, 작성 완료, 종료된 기수는 제외합니다.
- 안내 날짜의 오전 9시부터 `오늘 밤 11:59까지 작성해주세요.`와 작성 링크를 표시합니다.
- 다음 날부터는 `아직 남기지 않은 답변이 있어요. 지금도 작성할 수 있어요.`로 표시합니다.
- 답변 저장 후 홈과 목록의 데이터를 갱신해 안내를 없앱니다.
- 접속 또는 화면 재조회 시 현재 날짜와 작성 상태로 계산합니다. 별도 발송 내역, 예약 작업, 휴대폰 푸시, 카카오 또는 이메일 발송은 없습니다.

## 적용과 검증

적용 마이그레이션: `supabase/migrations/20260920062638_talk_group_schedule.sql`.

2026-09-20 `20260920071950_meeting_based_talk_deadlines.sql`을 적용해 그룹 모임 기준 공개·마감 계산으로 변경했습니다. 회원 화면의 그룹 이름·희망 요일 입력은 제거하고, 운영자에게는 그룹별 사전 질문·실천 기록 마감을 함께 표시합니다.

이어 `20260920072301_first_talk_opens_on_cohort_start.sql`로 1주차 공개만 기수 시작일을 쓰는 예외를 적용했습니다. 기존 마감 기준은 유지합니다. 격리 DB에서 129개 검증과 실제 DB의 1~8주차 공개·마감 조회를 통과했습니다.

그룹·그룹 구성원·모임 일정·희망 요일 표와 RLS를 추가합니다. 프로필 표의 본인 조회 잠금은 유지하며, 배정에 필요한 닉네임·회원 식별자·희망 요일·그룹만 운영자 함수로 조회합니다.

2026-09-20 사용자 승인 후 READ_ME 원격 DB에 적용했습니다. 적용 이력, 새 표 4개의 RLS, 비로그인 일정 조회 차단, 회원 권한의 8주 일정 조회와 운영자 권한의 배정 명단 조회를 확인했습니다. 그룹과 실제 회원 배정은 만들지 않았습니다. 실제 로그인 화면에서 희망 요일 저장 → 그룹 배정 → 일정 저장 → 답변 작성 → 안내 제거의 연결 검증은 아직 하지 않았습니다. 웹 배포와 커밋·푸시는 별도입니다.

Supabase 보안 점검에는 로그인한 사용자가 호출할 수 있는 SECURITY DEFINER 함수 안내가 표시됩니다. 새 일정·명단 함수는 각각 함수 내부에서 기수 참여 및 운영자 권한을 검사하며, 비로그인 실행 권한은 제거했습니다. [점검 항목 설명](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable). 기존 공개 인터뷰·가입 함수 관련 안내와 유출 비밀번호 보호 미설정 경고는 이번 적용 범위에서 변경하지 않았습니다.

격리된 PostgreSQL 검증:

```text
node scripts/test-talk-groups.mjs <PGlite 설치 경로>/dist/index.js
```

권한, 프로필 잠금, 정원, 기수 전체 답변 조회와 주차별 선작성 잠금, 날짜 경과 후 저장, 요일별 D-2·일요일 계산, 연말 경계, 오전 9시·자정·작성 완료 알림 조건을 확인합니다. 실제 회원 정보는 사용하지 않습니다.

`20260920073001_cohort_wide_talk_answers.sql`을 원격 적용했습니다. 1~8주차 각각 미작성 시 잠금, 작성 후 같은 기수 동료 답변 공개, 다른 기수 및 비회원 차단을 포함해 총 161개 검증을 통과했습니다. 기존 답변과 그룹 배정 데이터는 변경하지 않습니다.
