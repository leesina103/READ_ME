# 인터뷰 후 모임 선택과 확정

가입 신청서 `/membership/apply/1`에서 가이드 소개와 모임 요일·시간을 보고 모임 하나를 필수로 선택합니다. 신청 카드에는 회차별 날짜를 나열하지 않으며, 확정 후 `/my`에서 전체 날짜를 확인합니다. 추가 희망 모임과 ‘선택 안 함’은 제공하지 않습니다. 신청 자체로 자리가 확정되지는 않습니다.

## 운영 순서

1. `/admin/cohorts`의 그룹 관리에서 가이드별 그룹을 만듭니다. 같은 시간의 그룹을 여러 개 만들 수 있습니다. 그룹 이름은 운영자에게만 보입니다.
2. 그룹을 펼치고 네 번의 날짜·시각을 입력합니다.
3. 가이드 이름, 가이드 소개, 장소, 회차별 소요 시간을 입력하고 필요하면 ‘가입 신청서에서 이 모임 선택 허용’을 켠 뒤, 맨 아래 ‘모임 정보 저장’을 누릅니다. 안내와 일정은 모두 함께 저장되며, 실패하면 어느 쪽도 바뀌지 않습니다.
4. 기수 자체의 신청 접수도 열려 있어야 신청서에 나타납니다. 네 번 모두 앞으로의 일정이어야 합니다.
5. `/admin/applications`에서 신청자가 고른 모임을 확인한 뒤 ‘승인하고 모임 확정’을 누릅니다.
6. 신규 회원은 가입 완료 시, 재참여 회원은 승인 시 선택한 모임에 연결됩니다. `/my` 상단 ‘내 모임’에서 가이드 이름과 소개, 장소, 전체 날짜·시간을 확인합니다.

## 정원과 변경

- 확정 정원은 기존 운영 기준인 6명입니다. 승인 후 아직 가입하지 않은 사람도 자리를 차지합니다.
- 검토 대기 신청은 자리를 차지하지 않습니다. 6명이 확정되면 새 신청 선택지에서 빠지고, 남은 대기 신청의 추가 승인도 차단됩니다.
- 다른 모임으로 자동 변경하지 않습니다. 정원 초과나 일정 변경은 신청자와 먼저 상의합니다.
- 가이드나 일정을 고치면 신청 검토 화면과 `/my`에도 변경 내용이 반영됩니다. 변경 사실은 운영자가 별도로 안내해야 합니다.
- 기존 신청과 회원 배정은 그대로 유지합니다. 기존에 모임 선택 없이 들어온 신청은 종전처럼 승인할 수 있습니다.
- 신청 또는 초대장이 연결된 그룹은 삭제할 수 없습니다. 모집을 멈추려면 신청 접수를 끕니다.

## 검증과 배포 상태

- 2026-09-28 운영 DB에 `membership_group_selection` 변경을 적용했습니다.
- 적용 직후 기존 그룹은 2개, 회원 배정은 3건이며 새 신청 접수는 모두 꺼져 있습니다. 실제 가이드 정보와 일정 등록이 필요합니다.
- 신규 가입, 재참여, 정원과 조회 권한을 격리된 PostgreSQL에서 검증했습니다. 테스트는 실제 회원 데이터를 쓰지 않습니다.
- 로컬 화면은 포트 3000에서 확인합니다. 웹 코드의 운영 배포와 Git 커밋·푸시는 별도입니다.
- 비로그인 신청용 조회·저장 함수는 의도적으로 공개되어 있습니다. 조회는 모집 모임 안내만 반환하고, 관리자 함수는 운영자 확인을 거칩니다. Supabase의 [공개 SECURITY DEFINER 함수 점검](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable)은 이 공개 함수에도 표시될 수 있습니다.
