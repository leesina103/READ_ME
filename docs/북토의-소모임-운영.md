# 북토의·소모임 운영

## 화면

- 회원: `/membership/activities`에서 북토의·소모임 목록, 내 신청, 모임 제안을 확인합니다.
- 모임 상세: 신청 전에 정확한 참가비, 포함 내역, 별도 비용과 환불 마감을 확인합니다.
- 운영자: `/admin/activities`에서 모임 등록·수정, 입금 확인, 환불 완료와 받은 제안 내용을 확인합니다.
- 제안은 접수만 합니다. 회원에게 보낸 제안 목록이나 검토 상태를 표시하지 않고, 전송 후 ‘제안을 보냈어요.’만 안내합니다. 운영자는 기존 제안을 포함해 받은 내용을 볼 수 있으며 검토 완료 버튼은 없습니다. 기존 DB의 상태 값은 보존하지만 화면과 접수 흐름에서는 사용하지 않습니다.
- 회원 소모임 목록 카드에는 고정 참가비를 반복 표시하지 않습니다. 북토의 카드의 개별 참가비와 모임 상세의 참가비는 유지합니다. 상세의 가이드 면제·입금 대기 포함·운영 문의·한국 시간 안내 문구와 가이드 본인의 신청 영역은 숨깁니다. 실제 참가비·정원·환불·가이드 면제 정책은 바뀌지 않습니다.
- 현재 가이드 모임은 운영자 계정으로 등록합니다. 개설한 계정이 진행 가이드이며 신청과 참가비가 면제됩니다. 일반 회원에게 개설 권한은 없습니다.

## 참가비와 환불

- 북토의는 30,000~40,000원 범위에서 모임별로 설정합니다.
- 소모임은 3,000원입니다. 식비·입장료 등 별도 비용은 모임에 명시합니다.
- 모임 시작 시각에서 정확히 7일 전까지 취소하면 전액 환불합니다. 이후에는 환불하지 않습니다.
- 가이드 사정으로 모임을 취소하면 입금한 신청자 전원을 전액 환불 대상으로 표시합니다.
- 날짜와 시각은 한국 시간 기준입니다. 실제 반환 송금은 운영자가 별도로 진행하고, 송금 후 환불 완료를 기록합니다.

## 신청 처리

1. 모임 정보와 운영 계좌를 입력합니다. 오픈채팅 초대 링크와 비밀번호는 선택 사항으로, 비워 두고 개설한 뒤 수정 화면에서 추가할 수 있습니다. 링크는 주소 형식 제한 없이 입장 안내 문구도 입력할 수 있습니다. 비어 있으면 확정된 참여자에게 채팅방 준비 중으로 표시합니다. 참가비 포함 내역·별도 비용·운영 문의는 입력하지 않습니다. 새 모임에는 유형별 포함 내역과 활동 비용 별도 안내가 자동 저장됩니다. 기존 모임의 안내는 수정 시 보존됩니다. 문의는 사이트 공통 안내를 사용하며, 현재 하단 문의 버튼의 실제 채널 주소는 아직 설정되지 않았습니다. 작성 중 상태에서는 회원에게 공개되지 않습니다.
2. 회원이 환불 기준에 동의하고 입금자명을 입력하면 신청됩니다. 입금 대기 신청도 정원에 포함됩니다.
3. 신청별 코드를 붙인 입금자명과 운영 계좌를 안내합니다. 코드 입력이 어려운 경우 신청자가 운영 문의로 알려야 합니다.
4. 운영자는 실제 은행 내역과 금액을 확인한 뒤 참여를 확정합니다. 확정된 회원만 상세 화면에서 채팅방 정보를 조회할 수 있습니다.
5. 입금 대기 신청은 자동 만료시키지 않습니다. 실제 입금이 없음을 확인한 경우 운영자가 미입금 취소해 자리를 비웁니다.
6. 입금 확인 전에 회원이 취소했다면 입금 여부 확인 대상으로 남습니다. 실제 입금이 있으면 이를 기록하고 취소 시각 기준으로 환불 여부를 계산합니다.
7. 취소 시 웹에서 채팅방 정보 조회를 차단합니다. 이미 입장한 회원의 퇴장과 취소 안내는 운영자가 채팅방에서 별도 처리합니다.

신청자가 생긴 뒤에는 일정·장소·가격·책·제공 내역·가이드를 변경할 수 없습니다. 변경이 필요하면 모임을 취소하고 새로 등록합니다. 이전 신청의 입금·환불 확인이 끝나면 다시 신청할 수 있습니다.

운영자 화면에서는 기존 활동 수정 시에도 모임 시작 시각과 신청 마감을 과거 시각으로 새로 변경할 수 없습니다. 이미 지난 시각을 그대로 유지하면서 채팅 안내 등 다른 정보를 수정하는 것은 허용합니다. 웹 서버에서 검사하며, 존재하지 않는 달력 날짜도 거절합니다.

## 데이터베이스 적용과 검증

적용 마이그레이션: `supabase/migrations/20260920054923_membership_activities.sql`

채팅 링크 선택 입력 적용: `supabase/migrations/20260920060428_optional_activity_chat_link.sql` (원격 적용 완료). 빈 값 개설과 신청 후 자유 형식 안내 추가를 롤백 테스트로 검증합니다.

새 표 5개(모임, 입금 안내, 채팅방 정보, 신청, 제안)와 접근 정책·상태 처리 함수를 추가합니다. 기존 프로필 조회 정책은 변경하지 않습니다. 일반 회원은 자신의 신청·제안만 조회하고, 입금 확인·환불 완료 처리는 운영자만 할 수 있습니다.

2026-09-20 READ_ME 원격 Supabase에 적용했습니다. 실제 DB에서 회원·운영자 권한, 신청·입금 확인, 정원, 취소·환불 경계 및 제안 처리를 검증했고, 검증 데이터는 모두 롤백했습니다. 새 표 5개와 함수에서 보안 점검 경고는 발견되지 않았습니다. 기존 가입·인터뷰 기능 등의 보안 점검 항목은 이번 변경 범위에 포함하지 않았습니다.

웹 화면 전체의 로그인 후 신청·확정 연결 검증은 아직 수행하지 않았습니다. 로컬의 화면 구성·반응형·비로그인 접근 차단과 DB 처리 검증은 완료했습니다. 실제 모임과 운영 계좌·채팅방 정보를 등록하면 운영을 시작할 수 있습니다. 웹 코드의 서비스 배포는 별도입니다.

로컬 SQL 검증은 별도 임시 경로에 설치한 `@electric-sql/pglite@0.3.14`로 실행합니다. 프로젝트 의존성은 변경하지 않습니다.

```text
node scripts/test-activities.mjs <임시 설치 경로>/node_modules/@electric-sql/pglite/dist/index.js
```

가상의 운영자·회원·비회원을 만들고 `supabase/tests/membership_activities.sql`의 권한·정원·환불 경계 검증을 수행합니다. 검증 후 신청과 모임이 롤백되었는지도 확인합니다.
